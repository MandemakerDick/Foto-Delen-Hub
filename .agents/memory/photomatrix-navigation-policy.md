---
name: PhotoMatrix navigation policy
description: Where the native bottom menu should remain visible and where it should disappear.
---

Keep the bottom menu accessible while browsing public lists and photo, club, theme, and photographer details. Hide it for focused sign-in, invitation, upload, and editing flows, where an accidental tab change can interrupt work. Preserve old links when changing route ownership.

Every deliberate bottom-menu tap should open that tab's starting page at the top, not restore a nested detail page or a prior scroll position. Gallery filters can remain in place; resetting the page does not require discarding the user's selection.

For a signed-in photographer viewing their own profile, show the same public Photographer detail page with an owner-only Edit action; avoid a duplicate intermediate "linked profile" screen or Sign out button beside the edit action.
When View profile is opened from My photos, keep the shared Photographer detail inside My photos' stack so My photos remains selected and Back returns there. Public discovery links may still open that detail inside Gallery.
Related club, theme, photographer, and photo links should stay in the entry tab's stack (My photos, Liked photos, or Gallery) so Back returns to the immediately preceding page rather than switching tabs.

Follow/Unfollow in native needs a signed-in Home entry point to followed photographers, not an extra bottom-menu item by default. The user raised a separate bottom-menu item but did not settle it; the existing menu is already crowded.

**Why:** The user found it cumbersome to back out of detail pages once or twice just to reach the bottom menu, and explicitly agreed to the browse/detail versus focused-form distinction. They later asked for their own profile to match the public detail page instead of a separate account-link status screen. They reported that View profile from My photos unexpectedly selected Gallery, and later that its Club link switched to Gallery so Back returned there rather than to their profile; tab ownership must follow the entry point throughout the detail chain. A Club detail's Back landed on Photographers instead of its list; explicitly pushing the list's detail did not resolve the same failure for Themes on Samsung. The user later corrected the entry point: those directory lists were opened via Home shortcuts, not Gallery. On Android, tapping Gallery again sometimes returned to the last Photographer page. An initial Samsung pass did not hold: the user reported the same issue later, even after a nested tab navigate-to-index change. A deep-linked tab stack can have a detail route at index zero, leaving nothing to pop. The user asked for native Follow/Unfollow with a Home entry for signed-in members and noted the bottom menu is already full. They later confirmed the Follow and Home directory Back paths worked on Samsung after the explicit list-origin return paths, but found a new case where Following from Home remained visible on Gallery tab taps.

**How to apply:** Add new browsing/detail routes inside the appropriate entry tab's stack, reusing the detail component when two tabs can open the same profile; put standalone forms outside tabs or hide the bar while an inline form is active. Keep explicit list-origin return targets for Gallery directory details: push alone did not guarantee the correct Back destination on the Samsung. Home shortcuts enter Gallery's tab stack, but the list's Back must return Home; directly opened lists return Gallery. The user prefers icon-only arrows, with localized accessibility labels rather than visible destination text. A directory list can itself be the first screen in Gallery's stack, so do not assume an automatic Back arrow. In classic tabs, a bare navigate to Gallery restores its saved nested page; explicitly target its index when that page is not the index, but leave an already-open index alone or its search/filter state is lost. Do not pair that navigation with an independent pop/replace reset, which can race. Verify on an installed build, including a directly opened detail and the Following → My photos → Gallery route; iOS native tab behavior needs its own check. Do not ship a follow action without a way to reach followed photographers.
